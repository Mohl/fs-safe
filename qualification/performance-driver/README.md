# Root exact identity performance driver — source only

Launch is disabled. The driver coordinates the already frozen 192-process experiment using the external benchmark runner, existing offline assessor, and byte-identical bounded.py/settlement_control.py helpers. It adds no lease, transport, setup, build, install, network, retry or collection framework. No driver, product, benchmark, assessor or test was executed while preparing it. The parent owns host admission, artifact transport, source review, activation, collection and lease release.

CLI: `python -I run-performance.py ACTIVATION.json NEW_UNUSED_OUTPUT`. All runtime packet, repository, toolchain, artifact and evidence paths come from activation or the bound functional readiness candidate. `activation.template.json` remains launch:false/executionReady:false. Parent creates a separate reviewed activation with both true and driverManifestSha256 set to this source manifest's digest. The source manifest remains unchanged and false. Output and attemptClaimPath must be canonical, unused paths outside source/harness/packet directories; the claim must also be outside the new output. Claim creation is exclusive and permanent, including on failure. The same activation cannot be invoked again with another output to obtain replacement measurements.

`functional.audit` points to a separate parent-owned acceptance receipt shaped like acceptance-receipt.template.json. It binds the immutable readiness-candidate.json, functional-final.json and functional outer bounded exit receipt, plus the immutable independent audit file and its accepted PASS/no-findings conclusion. The original audit may use its existing format. Readiness remains pending/launch:false, and both historical evidence files keep internalDeclarationInspectionAccepted:false. The acceptance receipt alone records approval of exactly root-context.d.ts, root-observed-path.d.ts and root-walk.d.ts, with the emitted nine A/B/patch hashes. Public entrypoints, exports, API snapshot and strict installed-consumer typecheck must be accepted as equal. Complete declaration equality is deliberately not a gate.

Functional child settlement is checked against each expectedExit. Only regression-A expects exit 1, with its exact nine expected failures and three expected passes; candidate regression expects twelve passes. All other functional steps and the outer process require exit 0, no failure and joined settlement. The eight A/B × Node22/24 × off/require installed lanes must exist with their expected scenario count and immutable report hashes. The readiness candidate's four consumer records and Node24 runtime record are used verbatim, including sourceRole A/B. Tarball sha512 values are SRI strings (sha512-BASE64), not hex digests.

Before timing, the driver verifies the immutable functional/performance source packets, exact clean A/B and harness commits/trees, all common native build inputs, the single common-addon provenance, installed root/native file inventories, root/addon tarball bytes/SRI, package locks, compiled distribution hashes and fresh Node24 version/binary. Identical addon tarball bytes are required in all four consumers; same-source pairs share root tarballs. The harness's complete source inventory and existing runner hash are checked. Parent-reviewed host provider/lease/instance identifiers are retained without querying them; actual full initial CPU affinity and filesystem device/block size are checked locally. Host admission must supply the full initial 16-CPU mask and its lowest CPU. The driver then pins itself and every child to that CPU.

Every frozen slot is attempted exactly once, sequentially. A child gets at most 180 seconds; the entire driver gets 2,700 seconds, with eight seconds reserved before child dispatch for bounded settlement. Raw request/stdout/stderr/exit files, timing start/elapsed journals, partial reports, activation bytes, before/after inventories and a progressively saved campaign.json remain in the new output on all failures. The existing cancellation/settlement owner joins each child's process group before another dispatch. The parent must retain its outer deadline and settlement owner for collection even when the driver cannot finish. There is no automatic repeat, exclusion or retiming.

Only after all 192 slots, unchanged final bindings and successful settlement does the driver invoke the frozen offline assessor. Its receipt and exact derived binding are retained. A complete statistical/control HOLD stays complete/HOLD; execution, validation or deadline failure stays incomplete/HOLD. The recorder now retains a dlopen attempt before any fallible filename conversion/read/check/forwarding, with matched outcomes: off requires zero attempts/outcomes, require one successful pinned load plus actual observeDirectory witnesses. The v1 performance packet is preserved separately; this driver binds the narrow repaired v2 without altering its schedule, workloads or thresholds.
